# 佳明国区直连验证

目标是电脑完成首次授权后，由ESP32直接读取佳明国区并续期；本机验证工具不是转发网关。

## 已完成的电脑端验证

2026-10-28，用户自行在本机页面输入国区账号及密码，授权成功。账号支持手机号输入；如果佳明在密码登录后要求MFA，工具会显示独立验证码输入框，不把短信验证码当作账号密码。

下列请求使用普通Python `requests` TLS、固定国区域名、禁自动重定向、无API Cookie、关闭环境代理。所有请求均返回HTTP 200且可解析为JSON：

| 检查 | 响应大小 |
| --- | ---: |
| 用户资料 | 3,103 B |
| 当日汇总 | 3,444 B |
| 强制刷新DI令牌 | 3,020 B |
| 用续期结果重新读取当日汇总 | 3,444 B |
| 睡眠 | 104,820 B |
| 身体电量 | 1,246 B |
| 最近运动 | 4,283 B |
| HRV | 9,699 B |

当日汇总包含有效步数字段，登录返回完整DI access token、refresh token和client ID，刷新结果保存后再次读取成功。所需简报指标有返回值。报告只在本地保留选定字段，不保存原始资料、运动路线、完整睡眠曲线或账号密码。

这一步证明电脑普通HTTPS链路可用；ESP32真机验证如下。

## 已完成的ESP32真机验证

同日用原生ESP32-S3身份烧录验证固件，写入哈希校验通过，未操作CH340。导入最新DI令牌后临时清空设备网关地址，设备以ESP-IDF原生TLS直接请求国区服务器：用户资料、当日汇总、强制续期、续期后重新读取全部HTTP 200，完整响应与JSON字段校验均通过。

更新后的令牌保存到 `storage` 分区的 `garmin/tokens` 单一NVS blob。随后执行硬件重启，从NVS恢复授权，再次在网关地址为空时完成同样四步验证；再次保存轮换结果。两轮结束后均完整恢复原设备设置。第二轮结束内部空闲内存约160 KiB，历史最低约79 KiB，PSRAM空闲约7.95 MiB。

本机登录辅助工具已停止，后续测试使用设备自己保存的授权。当前固件NVS未启用加密；本次没有修改eFuse或宣称令牌加密存储。长时间授权是否被服务端撤销仍需实际使用观察，短时强制续期与重启测试不代表永久免维护。

## 本机工具

需要Python 3.12+。在独立虚拟环境安装 `tools/garmin-requirements.txt`，然后运行：

```powershell
python tools/garmin_probe.py
```

打开 `http://127.0.0.1:8791/`。服务只绑定回环地址；POST检查Host、Origin及随机CSRF值。页面不加载第三方脚本或字体。凭据通过本机页面提交后，只用于佳明官方授权；密码和验证码不写日志、不回显、不写文件。所有授权令牌和验证结果保存在Git忽略的 `.local/garmin-probe/`。

Windows部署时，先为该私有目录设置当前用户与SYSTEM的NTFS访问权限；不能把Python的 `chmod(0600)` 误当成Windows访问控制。本次运行已在用户输入前设置该目录ACL。

`tools/garmin_device_probe.py` 使用已有 `.local/device-access.json`，仅连接配置的私有IP设备；导入最新令牌后不再转发任何Garmin请求。其设备验证阶段临时清空网关地址，结束恢复原配置。不要让电脑和设备并发刷新同一份refresh token。

## 来源与限制

采用MIT项目 [python-garminconnect](https://github.com/cyberjunky/python-garminconnect)，固定提交 `3eee7a4db6c2242967aae1780b8839599ea7dcbb`。登录使用该库；普通HTTPS读取与刷新验证在本机工具中独立执行。

数据来自手表已同步至Garmin Connect的云端记录，不能当作手表实时遥测。接口为非官方接口；若授权被撤销或接口变化，可能需要再次登录。认证凭据仅用于读取简报及正常授权续期，不提供修改运动记录的功能。

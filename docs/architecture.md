# 实现结构

## 数据路径

```text
SHTC3 ──I²C──┐
PCF85063 ────┤  ESP32-S3 ──SPI── 800×480墨水屏（竖屏480×800）
三向拨轮 ────┘     │
                  ├── Wi-Fi / HTTPS ── Met官方JPEG图片
                  │                   ESP32解码、黑白转换、缓存
                  ├── Wi-Fi / HTTPS ── Garmin Connect国区
                  │                   ESP32读取、令牌续期、简报缓存
                  │ Wi-Fi / HTTP，使用网关令牌
                  ▼
             电脑 Paperdesk 网关
                  ├── 和风天气 HTTPS API：实况 + 三日预报
                  └── 本机 Codex app-server：只读账号额度
```

设备网页负责网络、网关连接、显示偏好、校时、画廊与佳明状态；电脑网关网页负责天气凭据与服务状态。天气API凭据保留在电脑上，Codex登录状态不复制到设备。画廊独立直连官方图片服务，不携带网关令牌或其他账号凭据。佳明另用仅监听本机回环地址的首次授权工具；导入后由设备保存并轮换自己的佳明令牌，日常同步不经过电脑。0.2.0不再包含订单与快递路径。

## 界面与绘图

首页集中显示日期时间、板载温湿度、天气和Codex剩余额度。0.5.0将原Codex详情页替换为月历，0.6.0增加画廊，0.7.0增加佳明简报；当前五个内容页为首页、天气、月历、画廊、佳明，Codex的首页显示与网关同步保留。上下拨与自动轮播只循环五个内容页，设置通过长按进入并暂停轮播，默认页也只能选五个内容页。

画布为48000字节的1位黑白位图，逻辑480×800转换为面板原生800×480。中文字库由Noto Sans SC离线生成，设计字号与字格尺寸分开：字格包含完整上伸部和下伸部，避免底部笔画裁切。天气图标使用有限的纯黑白形状，按可见像素边界居中；文字与数字以实际字形边界对齐。

首页有两套布局：`home_style=0` 为“精密桌面钟”，使用Barlow Condensed数字字库；`home_style=1` 为“编辑式微衬线”，使用DM Serif Display数字字库。中文标签保持Noto Sans SC。两套布局共享同一份天气、传感器和额度快照；风格切换不会产生额外的上游API请求。

`home_style` 同时由拨轮设置和设备网页修改，保存在NVS。旧配置缺少该字段时回退到0；HTTP写入只接受整数0或1。风格变化置位全刷请求，绘图循环消费请求后全屏刷新，避免只替换部分像素留下旧布局残影。首页的Codex数值与进度条都表示剩余比例。

0.4.0为天气详情增加独立的 `weather_style`：0为“天气日报”，使用DM Serif Display大温度与三列预报；1为“温差观测”，使用Barlow Condensed大温度与三天温度区间横条。两款天气页都读取同一份现有天气快照，不增加上游接口。横条在三天共用的温度刻度上绘制每天最低至最高温度的区间，不插值为逐时数据；缺失值不转换成0℃，缺少有效区间时不绘制横条。

拨轮设置中的“天气风格”和设备网页“显示”中的“天气页风格”读写同一字段。`weather_style` 与 `home_style` 分别保存在NVS中，独立校验并切换；旧配置缺失时默认0。每种风格的变更保留各自的全刷请求，直到对应页面下一次绘制时消费，避免在其他页面提前清除请求。

首页不显示重复时间、IP、调试文案或常驻操作说明。配网信息放在设置中，错误状态与缓存时间保持可见。

## 离线月历

月历采用大月数字与七列公历/农历网格。左上显示年月与“本月/下月”；右上角的今日MM/DD、星期、农历、干支生肖年和下一节气取自设备当前日期，下半屏按当前浏览月份排布。今天使用反白格子，节气日以节气名替换农历日标签；农历月首使用月名，十一月、十二月显示“冬月”“腊月”，闰月采用“闰六”等两字简称，保持20px标签字号。月历页短按在本月和下月之间循环，上下拨切换内容页，长按进入设置。

公历排布由设备本地日期计算，农历与节气由固件内嵌的香港天文台官方对照数据查询，支持1901-01-01至2100-12-31，共73,049个公历日。查看下月不会改变今日信息或设备时间，查询也不依赖SD卡、网络或网关。超过数据范围时保留公历排布，农历与节气显示不可用；不将缺失记录推算为有效值，也不加入法定假日、休息日或调休推断。

`tools/generate_calendar_data.py` 从官方年表生成 `firmware/main/calendar_data.h`，以2,475个农历月起点和4,800个节气日期编码，打包数组占29,100字节，另有少量名称与边界常量。来源、SHA256及生成记录保存在 `assets/calendar/source.json`。正常构建直接使用生成的头文件，不需要Python或网络；原始年表缓存保存在已忽略的 `.local/calendar-cache`，不需要随设备运行。

## 直连黑白画廊

画廊使用24幅Met公共领域作品的精选目录，中文短译名与原始编目事实保存在 `assets/gallery/catalog.json`，由 `tools/build_gallery_catalog.py` 离线生成 `gallery_catalog.h`。这是有限目录按日循环，不是依赖运行时搜索的无限作品流；每日选择取自设备的中国标准时间日期，短按可以请求下一幅。

独立画廊任务通过HTTPS直接获取 `images.metmuseum.org` 上的JPEG，启用证书验证、限定图片域名、禁用自动重定向，并对下载时间与大小设上限。此路径无需电脑网关、API Key或SD卡，源图片地址已经过官方元数据核对。下载失败时尝试有限数量的后续候选；自动更新失败后延迟重试，手动连续换画也有限流。

`gallery_image.cpp` 使用TJpgDec在设备上解码baseline JPEG，限制输入为768 KiB、原图每边不超过4096px，按需要缩小解码尺寸并限制灰度工作内存。图片保持宽高比，居中适配432×544区域，转换为1位黑白位图后交给480×800页面绘制。渐进式或损坏的JPEG被拒绝，不覆盖此前有效画作；固件不把高分辨率JPEG作为屏幕帧长期保留。

成功获取的黑白位图、作品身份和取得时间保存在独立NVS缓存中，启动时校验并恢复。断网或更新失败时继续显示上一幅，状态与取得时间单独保留；从未下载成功时显示空状态。画作更新请求全刷，其他页面不会提前消费该请求。设备网页的“画廊”标签展示状态、作品信息、取得时间与官方来源，并提供换画按钮。

画廊与天气/Codex同步相互独立；电脑网关离线不阻止画廊联网更新。编译只使用目录和解码器源码，源图缓存 `.local/gallery-source` 仅供本地主机验证，不参与固件构建。

## 直连佳明国区

首次授权使用 `tools/garmin_probe.py` 和固定提交的 `python-garminconnect`，在电脑回环地址提供手机号／邮箱、密码及可选MFA输入页。密码和验证码只用于本次登录；得到可续期的DI授权后，工具用普通HTTPS分别验证读取、强制刷新和重新读取。账号密码不会导入固件，Python库也不运行在ESP32上。

`tools/garmin_device_probe.py initial` 从私有本机文件导入 `di_token`、`di_refresh_token` 和 `di_client_id`。导入接口要求设备管理码，验证期间临时清空网关地址，设备使用ESP-IDF原生TLS执行自己的读取→刷新→读取，之后显式保存最新令牌组并恢复网关配置。`resume` 使用NVS中的令牌验证恢复能力。电脑端原令牌在设备开始轮换后可能过时，不应再被并行用于刷新。

生产服务位于 `garmin_probe.cpp`，通过 `garmin.h` 提供启动、同步请求、快照与状态接口。请求目标固定为 `connectapi.garmin.cn` 和 `diauth.garmin.cn`，启用证书验证、禁用自动重定向，不依赖电脑cookie或代理。响应在有界PSRAM缓冲中串行接收：通常最多64 KiB，睡眠、身体电量与HRV最多512 KiB；下载原始响应仅在解析期间存在。

每轮同步先刷新授权，将完整的新access／refresh令牌组作为一个NVS blob提交成功后，才继续读取资料、当日汇总及可选指标。写入失败时保留RAM中的新令牌并停止后续请求；下一轮先尝试保存，避免又从旧refresh token发起轮换。后台同一时间只允许一个同步或探针任务使用授权。

正常同步结束后等待30分钟。短按、设备网页和设置页的同步动作共用60秒手动请求间隔；忙碌时忽略重复请求。401／403或刷新端点拒绝授权时停止自动重试，状态标为需要重新授权；429和网络错误进入30分钟退避，手动同步不能绕过。离线时保留简报缓存，重新联网后按到期状态继续同步。这里的请求仅用于授权续期与读取，不写入或修改用户运动记录。

`garmin_data.h` 是固件实际使用的纯数据解析层。按日汇总、睡眠、HRV和身体电量都核对返回日期；切到新一天时清空旧的按日指标，同日可保留有效旧值并注明缓存。未知值使用 `-1`，显示层呈现“—”；有效的0不会误判为缺失。最近一次运动独立保留 `activity_date`，不因简报日期变化而标为今天。

佳明的 `lastSyncTimestampGMT` 转为UTC秒级 `last_sync`，支持服务返回的秒、毫秒或UTC日期字符串，不再次按设备UTC+8扣减。`fetched_at` 单独记录设备成功读取当日汇总的时间；读取到旧云端内容不会改写手表的同步时间。只缓存展示需要的汇总数值、最近运动类型／日期／距离／时长、数据日期与状态，不保存全天曲线、运动轨迹或完整用户资料。

设备重启从 `storage` 分区的 `garmin` namespace恢复授权与简报。当前NVS未启用加密，首次导入沿用可信局域网内的HTTP管理接口；本机账号文件、设备地址与管理码均位于Git忽略的 `.local` 中。实现和实测范围以 [佳明验证说明](garmin-validation.md) 为准，文档预览使用合成数据。

## 接口

设备：`GET /` 显示网页，`GET /api/state` 返回状态；`GET/POST /api/config` 需 `X-Paperdesk-Token` 管理码。读取配置时不返回已保存密码或网关令牌，只返回是否已保存。`home_style` 与 `weather_style` 作为独立显示偏好随配置读写，各自只接受整数0或1；省略字段保留原值。

画廊：`GET /api/gallery` 返回当前作品、取得时间、缓存与忙碌状态；`POST /api/gallery/next` 请求后台换画；`GET /api/gallery/image` 提供当前432×544黑白PBM图供验证，尚未就绪时返回404。三个接口均需设备管理码。设备网页“显示”中的开机默认页允许0–4（首页、天气、月历、画廊、佳明），不允许设置页。

佳明：`GET /api/garmin` 返回展示快照、缓存状态、重新授权需求和距离下次到期的秒数，不返回账号或令牌；`POST /api/garmin/sync` 提交同步意图，后台继续执行频率限制与错误退避。`GET /api/garmin-probe` 返回探针的HTTP状态、响应大小及验证标志；`POST /api/garmin-probe` 接受首次令牌导入、`action=resume` 或 `action=save`。这些接口全部要求 `X-Paperdesk-Token`，用于展示的健康数据也不会由未认证接口公开。

网关：`GET /` 显示网页；`GET /v1/snapshot` 返回 `schema: 1` 的天气及Codex快照；`GET/POST /v1/config` 读取/更新配置；`POST /v1/refresh` 请求后台同步。所有 `/v1/` 接口需 `Authorization: Bearer <token>`。读取配置不回传已保存的API Key或网关令牌。

上游更新时间与网关快照生成时间分开保存。上游失败时可保留旧值，但带 `stale` 和错误描述；不能仅因设备成功拉取快照就将上游缓存称为最新数据。天气快照包含实况及预报的图标代码，设备根据代码选取图形。

天气详情仅使用快照现有的温度、天气描述、体感温度、风向、风力等级、湿度及三日最低/最高温度。预报日期保留上游日期，只有与设备当前本地日期相符时才能标注“今天”；跨日缓存仍显示其实际日期，不因数组位置或读取缓存的时间重新贴标签。
